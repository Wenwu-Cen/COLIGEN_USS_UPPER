# v3.9.1 Ubuntu 滚轮修复验证记录

日期：2026-11-11。环境：Ubuntu 22.04.5 x86_64，Tk 8.6 / X11（GNOME Wayland 下经 XWayland 运行），虚拟机 192.168.70.129。

## 问题与修复

v3.9.0 只绑定 MouseWheel。Ubuntu 的原生滚轮通过 Button-4 / Button-5 传递方向，delta 为 0，画布没有接收到已绑定的缩放事件。修复前在 VM 中实际生成 Button-4 后，比例仍为 0.15，Button-4 绑定为空。

v3.9.1 为 X11 绑定 Button-4 / Button-5，并统一解析按钮方向和 Windows 的 delta。缩放围绕鼠标位置，图例与控件保持位置；连续滚动期间缩放已有图元，停止后刷新网格、比例尺和最新数据。到达边界时准确停在最小 / 最大比例，空滚动不改变比例。已消费的事件停止向其他滚动控件传播。

WorkspaceCanvas 在收到有效滚轮后切换为手动取景。新数据和窗口尺寸变化保留比例，右键或「适应视图」恢复自动取景。此修改适用于共用画布的 20 探头和 17 探头显示，不改动通信协议。

## 回归

- Ubuntu 完整回归：**83 passed, 1 skipped**，31.34 秒。跳过项为 Windows 专用 Vector DLL。
- 新增 6 个 X11 回归用例，在原画布和桌面实际使用的 WorkspaceCanvas 上通过 Tk 事件分发生成 Button-4 / Button-5。覆盖鼠标锚点、图例位置、快速连续滚动、最大最小比例、零 delta、新帧刷新、窗口尺寸变化、右键复位。
- 滚轮、平移和界面专项合计 16 项通过。
- Windows 画布与版本等 5 项通过。原布局用例首次受本机既有 Tcl 文件读取异常影响，单独进程重跑通过。

发行程序自检已增加实际滚轮事件检查，避免只调用缩放函数而漏检 Linux 事件绑定。单文件程序自检通过，结果为 canvas_wheel_zoom = X11 Button-4/5；随包 ASC 样例解析 2997 帧、120 个点。

通过真实 Ubuntu 桌面快捷方式启动 v3.9.1，客户区 1440×833，无启动异常。桌面入口已切换到新版；原 v3.9.0 的 can_upper_config.toml 已复制到新版，内容哈希一致。证据保存在发布包 validation/ 目录。

本次验证范围为视图交互和发行包；TRACE32、TCP/IP 协议及 PDC 音效沿用 v3.9.0。安装更新时保留虚拟机中原有的 can_upper_config.toml。
