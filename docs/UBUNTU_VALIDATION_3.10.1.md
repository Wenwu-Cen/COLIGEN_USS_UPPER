# v3.10.1 设备连接区布局修复验证

日期：2026-11-11。Windows 11 与 Ubuntu 22.04.5 x86_64 共用此修复。

## 问题与处理

v3.10.0 把 Port 标签 / 输入框向左排列，又把 Probe Scheme 向下排列在同一容器中。Tk 的 pack 布局在此组合下把探头方案放进右侧剩余区域，导致英文标题及选项被截断。

v3.10.1 为 Port 建立独立整行容器，Probe Scheme 占用下一整行；TCP/IP 网络设置也单独成行。切换硬件、连接、断开后统一恢复布局。侧栏默认宽度维持不变。

## 已验证

Windows 本机界面检查在 100%、125%、150% 控件缩放下逐一切换 5 种硬件及 17 / 20 探头，共 18 组。方案下拉框宽度分别为 178、223、268 像素；英文标签及完整选项均位于容器边界内。无界面回调异常。

本版范围为布局和版本维护；数据解析、PDC 单位、探头方案和车型配置格式沿用 v3.10.0。

后续发行验证结果见随包 validation/ 目录。

## 发行验证结果

- Ubuntu 完整回归：123 项通过、1 项 Windows Vector DLL 专项跳过，44.30 秒。
- Windows 界面 / 硬件 / 车型 / 版本专项：17 项通过；1 项受本机 Tcl 初始化异常影响的布局用例，在独立进程重跑通过。
- Ubuntu 原生窗口按 100%、125%、150% 控件缩放验证全部可用硬件及 17 / 20 选项，共 9 组；Windows 共 18 组。通过控件边界、文本可用宽度及行顺序检查。Windows 实际窗口和 Ubuntu 截图均已核对，英文标签与完整选项显示正常。
- 两平台单文件发行程序自检通过：Windows MouseWheel、Ubuntu X11 Button-4/5、车型编辑与保存、17 探头 TCP/IP 解析正常。
- 本次只验证离线界面与发行程序。启动 Ubuntu 虚拟机完成原生构建，没有启动 TRACE32、复位或写入目标板。
- Ubuntu 安装保留原有用户车型库、探头方案及程序旁配置文件；旧版安装目录继续保留。
