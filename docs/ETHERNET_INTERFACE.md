# 17 探头以太网接口

新增以太网功能属于 17 探头方案。原有 CAN、Trace32、CS+ 和日志功能基于 20 探头方案，共用画布、数据面板和三档 PDC 音效。

## 数据依据

协议来自同级 SourceFile 中的 CANMatrix.h 及其引入的 uss_vendor_sdk.h。uss_test.c 实际外发以下五个 union，每包固定 512 字节，首字节为 1～5 的类型标识。结构体尾部的空余字节随包保留。

- 类型 1 对应 UssTxOriginalData_Info，包含原始距离、回波和探头状态。
- 类型 2、3、4 对应 UssTxPoint1Data_Info、UssTxPoint2Data_Info、UssTxPoint3Data_Info，依次包含点 0～29、30～59、60～89。
- 类型 5 对应 UssTxSlotAndPDCData_Info，包含 PDC、车辆位置和左右各 4 个车位。

以太网接收端支持上述外发变量的原始内存负载。CANMatrix.h 中旧的 UssUpperData_Info 1024 字节包在当前发送代码中被注释，当前接口使用五类 512 字节包。

## 连接

1. 启动上位机，点击「设备与显示」，在 Hardware 下拉框选择「TCP/IP」。
2. 打开“网络设置”，填写与 RTE 转发端一致的 IP、端口、字节序、结构体对齐和前缀长度。
3. 点击“在线连接”，状态栏先显示等待有效数据。收到有效包后显示点数、车位数和异常包数。
4. 点击「数据详情」检查点云、PDC 和车位。点云最多 90 点，车位支持左右各 4 个。点击「开始录制」可保存 TXT，通过「打开日志」回放。

默认选择 UDP，监听 0.0.0.0 的 50000 端口，负载使用小端、8 字节自然对齐和零字节前缀。此处为上位机接入默认值，需与实际 RTE 转发端配置一致。UDP 的 IP 为本机绑定地址，TCP 的 IP 为 RTE 服务端地址。TCP 模式会在断线后重新连接。

GUI 设置在本次运行中生效。长期配置可编辑 config/can_upper_config.toml 中的 ethernet 节。EXE 同目录的 can_upper_config.toml 优先于随包配置。

## 数据转换

- 点坐标按 E171_ObjCoordinateOutput.c 的发送赋值还原。外发 x、y 为厘米，上位机乘 10 转成毫米，采用前向 X、左向 Y。
- 车位坐标为毫米。底软横向右正、纵向前正，上位机转换成前向 X、左向 Y，并根据状态和类型过滤空车位。
- 底软左右车位时间戳分别为 uint32_t、uint64_t。默认自然对齐下，左车位结构体为 40 字节，右车位为 48 字节。
- PDC 输出距离已经是厘米，按原值传给画布。告警区间 1、2、其余有效远区间分别映射为长鸣、4 Hz、2 Hz，保留各探头的故障标志。系统停用时清除对应侧告警。
- 五类包分别计算新鲜度，默认 1 秒超时后清除对应点云、车位或 PDC。PDC 超时后停声。
- 录制文件保存 slot_capacity = 8，保证第 4 个左右车位可区分。旧日志继续使用默认的 6 车位布局。

## RTE 负载边界

UDP 数据报的可视化负载可以是一个 512 字节包，也可以是多个包的连续拼接。配置的前缀长度在每个 UDP 数据报起始位置跳过一次。数据长度和类型标识通过校验后才更新模型。

TCP 使用固定长度帧，每帧由配置长度的前缀和一个 512 字节包组成，支持跨接收调用拆包和一次接收多帧。对端断开时清空旧会话数据，再重新连接。

RTE 若增加 SOME/IP、序列化、变长头或分片，需按照实际传输协议先还原这五类完整负载。当前参数中的前缀长度只支持固定前缀。

## 本机联调

在上位机选择默认 UDP 设置并连接后，从项目根目录运行

```powershell
python .\scripts\test_ethernet_input.py
```

脚本发送 90 个模拟点、8 个模拟车位和远中近三档 PDC，默认持续 15 秒。按 Ctrl+C 停止。若修改了接收设置，可通过 --host、--port、--alignment 和 --byte-order 匹配。

协议布局已用同一份头文件经 C 编译器核对，覆盖 1、2、4、8 字节对齐。自动化测试覆盖 UDP、TCP 拆包、断线重连、超时和录制回放。真实 RTE 的网络封装和车辆端链路仍需联调确认。
