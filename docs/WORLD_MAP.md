# 固定地图与行车轨迹（4.4.1）

## 操作

1. 点击「设备与显示」，展开侧栏中的「视角与轨迹」。
2. 选择「固定世界坐标」：车辆按位置与航向移动、旋转，网格和摄像机保持固定。
3. 打开「显示行车轨迹」，以灰白色线条显示车辆参考原点走过的路径。
4. 「清空行车轨迹」删除已有路径，后续新帧继续记录。

「跟随车辆」是默认视角，车辆方向固定，周边数据使用原来的自车坐标显示。
TXT 日志切换到固定世界坐标或点击「适应视图」时，一次计算整段已记录车辆行程的边界，保证车身在整段回放中可见；播放和跳帧期间保持镜头不动，手动平移/缩放也不会被每帧重置。
两种视角都支持拖动、滚轮缩放、右键或「适应视图」。在线固定地图不会自动跟车，
车辆驶出画面时可手动平移或重新适应。切换视角会重新取景并清除已有测距标记。
固定地图中的测距标记保持在所选地图位置，车辆运动不会带动标记。

## 位姿与坐标

点云、线段、车位及探头安装位置均先进入自车坐标系：X 前、Y 左，单位 mm。
地图位姿为 `(x_mm, y_mm, yaw_rad)`，正航向从 +X 转向 +Y：

```text
map_x = car_x + local_x * cos(yaw) - local_y * sin(yaw)
map_y = car_y + local_x * sin(yaw) + local_y * cos(yaw)
screen_x = offset_x - map_y * scale
screen_y = offset_y - map_x * scale
```

车身、探头、点云、线段和车位使用同一变换，回波扇区及 PDC 朝向也随车旋转。
网格、轨迹和测距直接投影地图坐标，车辆每帧更新不会移动地图镜头。

- S20 CS+ 使用与本帧一起发布的 `sf_Upper_OdoOutSignal`。底软直接输出 `cAutoDrv_CarCenterPt`，位置已经是 mm，轴向为 X 右 / Y 前；绘图位姿为 `(odo_y, -odo_x, odo_ang)`，不能再乘 1000。
- TRACE32 保持现有前/左、m/rad 接口约定；USSV v1 串口/回灌也为前/左、m/rad，位置转 mm。不同源的里程计不能共用单位假设。
- CAN / ASC / BLF 使用 `0x640 VehiclePosition` 的绝对位姿，与本帧几何一起发布。
  位置按现有规则转为 `X = raw_Y - 32767`、`Y = -(raw_X - 32767)`，单位 mm；
  航向为 `(raw_Angle × 0.1 - 180)` 度再转 rad。
- 以太网沿用现有位置数据；当前协议没有提供航向，车辆方向保持零航向。
- 新 TXT 回放优先使用明确的绘图位姿；旧日志回退到 `odo_x/y/ang`（m、rad）。
  无运动位姿或里程计始终为零的日志不会根据车速推算轨迹。

轨迹采样点为后轴中心。车型配置填写轴距与悬长时，后轴中心在数据局部坐标中的
纵向位置为「后悬 − 数据原点距车尾」；缺少这些参数的旧协议按数据原点即后轴中心处理。
「固定世界坐标」以首次有效后轴中心位置为地图原点，此后原点不随车辆移动。
图中红点标出当前后轴中心，灰白色轨迹留在已经驶过的世界位置。
「跟随车辆」将后轴中心保持在视图原点，历史轨迹按同一世界路径转换显示。
对于静止障碍物，固件局部坐标与车辆位姿一致时，转换后的点/线会留在地图原位；
不会累计已经消失的历史障碍点。

## 轨迹与回放

轨迹记录后轴中心的世界位置，最小采样间隔 30 mm，最多保留 4000 点。
停车与纯转向不重复堆积轨迹点。关闭显示只隐藏路径，记录仍继续。
切换日志或重新连接数据源清空历史并重新确定后轴原点；切换视角保留历史。
「清空行车轨迹」保留当前地图原点，继续在同一世界坐标中记录后续路径。

TXT 回退、跨帧跳转，ASC/BLF seek 或循环，以及时间戳回退时，
从新位置重新开始路径，不连接跳过的区间。单次位置跳变超过 20 m 也会断开轨迹。
轨迹由实际显示的连续帧生成，不预先加载整段行程。

新 TXT 在 `[sf_Upper_OdoOutSignal]` 中保留原来的 `odo_x/y/ang`，并增加：

```text
map_x_mm = 1200.000000    map_y_mm = -500.000000    map_yaw_rad = 1.570796327
```

回放优先使用这些明确单位的地图字段，使 CAN 绝对位姿录制后仍能重现。
旧版解析器会忽略新增行，原始里程计数据和其他分节格式继续保留。

`tests/test_map_view.py`、`tests/test_canvas_map_view.py`、`tests/test_map_view_ui.py`

## 4.4.1 里程计兼容与录制

新 TXT 在 Odo 分节保存 `OdometryConvention = mm_right_forward`（S20 CS+）或 `m_forward_left`（TRACE32/USSV），同时保存标准 mm/rad 的 map 字段。录制、回放及再次录制都保留原始 odo 字段和约定，不重复转换。

早期 CS+ 录制没有单位/轴向标记，且 map 字段错误地等于原始 odo 的 1000 倍。解析器只在全部显式 map 字段匹配该旧公式、至少五个运动间隔有效且中位速度超过 100 m/s 时识别这一旧格式，按 S20 毫米右/前转换，并在加载状态提示修正。原始变量不改写。已声明约定、正常米单位行程以及独立 CAN map 位姿不进行此兼容转换。

解析器的旧格式识别依赖已有日志的字段和时间一致性，不能仅凭绝对位置大小确定单位。其他固件的异常日志应提供明确约定；原始字段始终可用于排查下位机数据。
